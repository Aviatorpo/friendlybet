# FriendlyBet - Release History

This is the historical changelog, moved out of `CLAUDE.md` to keep the always-loaded
project context small. `CLAUDE.md` keeps only the current version + the release process;
everything older lives here. Newest first.

## Recent versions

**v2.10.33** - Story score wording fix. The USA-Paraguay story no longer uses compact RTL-sensitive `USA 4-1 Paraguay` wording that could be read as the wrong side winning; it now says clearly that USA won 4-1 in both Hebrew and English. Version/cache bumped to v2.10.33.

**v2.10.32** - Pundit live-tournament freshness hardening. The dashboard Pundit no longer banks old editorial/news items for days during the live tournament. The generator now prioritizes current live/result/fixture facts from `public-data/matches.json`, filters news to short-lived same-day items only, refreshes `public-data/pundit.json` at least every few hours even when facts are quiet, and publishes `freshUntil` so the client can suppress stale feeds instead of presenting them as current. Cleared the stale banked `pundit-news.json` source file and tightened its validator to reject old/long-lived stories going forward. Version/cache bumped to v2.10.32.

Version/cache bumped to v2.10.31.

**v2.10.30** - Dashboard prediction CTA copy fix after kickoff. The completed-predictions CTA no longer tells users they can edit "until the World Cup starts" after the tournament has already begun. **v2.10.27** - Conservative live-match result display. **v2.10.21** - Recovery QR login picker fix. **v2.10.20** - Scoring and leaderboard data-path hardening. The dashboard refreshes the current user's displayed score/rank from the latest paginated pool read, and the leaderboard paginates live reads with a static snapshot fallback if Supabase is temporarily unavailable. Version/cache bumped to v2.10.20.

**v2.6.92** - Bracket app-chips now share the IMAGE on mobile, not a link. Root cause of the persistent "empty WhatsApp card": the chips did a `wa.me`/intent **link** share, so WhatsApp previewed the link via its OG scraper — and WhatsApp caches a link's preview per-URL and won't refresh it, even when the URL's `v` token changes (proven: the OG endpoint renders the full card on every fresh request, yet WhatsApp kept showing the stale empty preview). Fix: `_bracketChipImageShared(mode)` — in bracket mode, if the device can share files (`navigator.canShare({files})`), every chip attaches the real card PNG via the native share sheet, bypassing the OG scraper entirely (WhatsApp shows the actual picture). **v2.6.91** - Two share fixes found from real WhatsApp screenshots.
