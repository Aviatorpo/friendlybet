# FriendlyBet - Release History

This is the historical changelog, moved out of `CLAUDE.md` to keep the always-loaded
project context small. `CLAUDE.md` keeps only the current version + the release process;
everything older lives here. Newest first.

## Recent versions

**v2.6.90** - Three bracket-share fixes. (1) **Compact modal** — the celebration modal now fits above the fold in one screen: smaller card preview (196px), 4-column app grid (8 chips → 2 rows instead of 3), tighter vertical rhythm. Overrides scoped to `.bracket-share-modal-content` so the invite modal is untouched. (2) **WhatsApp/FB cache busting** — those apps key their link-preview cache by URL, so a previously-shared link keeps showing a stale (often empty) card. `_bracketShareUrl` now appends `&v=<hash of the bracket picks>`; `api/share.mjs` propagates `v` onto the `og:image` URL too. Same picks → same token (no edge-cache spam); changed picks → fresh URL → re-scrape. (3) **QR on the OG card** — the link-preview card (`lib/og-card.mjs`) was missing the "scan to enter" QR that the native canvas card already has. Added a QR (encodes `friendlybet.live`) in the footer; `api/og.mjs` pre-fetches it as a base64 data URI (`qrDataUri()`) so a flaky QR host can never break the whole render — it just drops the QR.

**v2.6.89** - Guard the bracket share chips against an empty preview. ### v2.5.70 - R32 restored with "team reached next round" scoring convention
- Reverted v2.5.69's "R32 is unscored" approach. New mental model: each correct knockout pick rewards the team for reaching the NEXT round. So a correct R32 winner pick = team in R16 (2 pts), correct R16 pick = team in QF (4 pts), correct QF = team in SF (8 pts), correct SF = team in Final (16 pts), correct Final = champion (32 pts). On top of the Final pick, the tournament_winner bonus (32 pts) still applies — predicting the champion correctly is worth 64 pts total.
- DEFAULT_SCORING_RULES (both modes) restored `round_of_32: 2` and doubled every subsequent stage (R16=4, QF=8, SF=16, Final=32). `getWizardRuleKeys` re-includes 'round_of_32'. Scoring-rule screen row arrays include 'round_of_32' again.
- `calcMaxPoints` re-adds the 16 × R32 term.
- `calculate-scores-v2.js` `bracketPosRuleKey(1..16)` returns 'round_of_32' again so R32 picks are scored normally.
- Removed the `knockoutFirst.unscoredLabel` branch from `koSingleRender` and the corresponding i18n key in both languages.
- Doubling progression now maxes each stage at ~32 pts: groups 48 (12×4), R32 32 (16×2), R16 32 (8×4), QF 32 (4×8), SF 32 (2×16), Final 32 (1×32), champion bonus 32, top scorer 20.
