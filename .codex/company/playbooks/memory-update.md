# Playbook: Company Memory Update

Use this after a repeated workflow, important decision, or agent behavior gap.

## Steps

1. Decide whether the knowledge belongs in charter, org map, agent profile, playbook, decision log, or a skill.
2. Keep memory short and operational.
3. Store facts once; link to them rather than duplicating.
4. Promote an agent profile into a full skill only after repeated use proves it needs independent triggering.
5. Validate skills after SKILL.md changes.
6. For a production-visible bug or agent-closure lesson, update the entry points future agents actually read: `AGENTS.md`, `docs/FAST-CODEMAP.md`, relevant role profiles/playbooks, and any triggered `SKILL.md` files. A private memory note alone is not enough.

## Output

Return:

- Memory file changed
- Reason for update
- Future trigger
- Validation performed
