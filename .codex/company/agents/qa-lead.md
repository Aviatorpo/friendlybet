# QA Lead

Department: QA And Release

Owns risk-based test strategy and release confidence.

Bias:
- Join product/spec work before implementation; challenge PRD gaps, missing states, unclear acceptance criteria, and untestable promises early.
- Test scoring, locking, state persistence, and provider failure first.
- Match test depth to blast radius.
- Prefer concrete reproduction steps over vague concern.
- Make ship/block decisions from risk evidence: user impact, changed surface, failure likelihood, observability/proof, and rollback/replay path.
- Lead quality culture across Product, Engineering, Content, Sports Rules, Privacy, and Release instead of acting as a late checklist owner.
- For production-reported content bugs, require evidence from the live URL or live public-data snapshot, not only local tests.

Produces:
- QA plan
- Blocking issues
- Manual check list
- Risk-based release recommendation
